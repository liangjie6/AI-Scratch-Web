# 回滚遗失内容恢复计划

## 1. 目标

依据实施文档/修复问题.md、幸存的项目拆分方案和当前工作区，恢复被 Git 回滚抹掉、但仍属于产品基线的代码、测试和协议变更。恢复后的实现必须通过后端测试、前端单元测试、生产构建，并保留当前工作区中与本任务无关的用户改动。

## 2. 恢复内容摘要

### 2.1 后端与 Provider

- 增加 GPT_API_KEY、GPT Responses API 地址和 gpt-5.6-sol 模型配置，并提供独立的 key 校验。
- 将模型档位恢复为 normal / advanced / super，思考强度恢复为 low / medium / high / xhigh / max。
- normal 使用 Agnes，advanced 使用 DeepSeek Chat Completions，super 使用 GPT /responses；实现 Responses SSE 的内容、推理、错误和 usage 解析。
- 收集层对断流做最多两次指数退避重试；重试请求关闭推理、使用低强度，且丢弃上一次半截输出。
- 对 advanced / super 统一启用结构化输出；日志只保留请求规模和结果统计，不打印完整 prompt、payload 或模型输出。
- 缩短修复上下文，补充计划复用协议：前端可携带已确认的计划，后端跳过重复规划。
- 收紧项目资源操作契约，并让 created_sprite 正确引用前置的 add_sprite 或 add_builtin_sprite。

### 2.2 项目生成协议

- 将项目模式从一次返回 ProjectPlan + block_programs 改为 ProjectManifest + project_program：清单只描述资源、程序目标意图和共享状态，不嵌入 ProgramIR。
- 后端新增清单与单目标程序 schema、提示词、repair 流程和 SSE 事件；移除旧 project_plan / project_ready / block_programs 合同，不保留兼容分支。
- 前端新增 manifest 类型和校验，资源阶段沿用现有准备/确认/事务回滚，资源提交后按逻辑 target 串行请求并注入每个 ProgramIR。
- 真实 VM target ID 只在前端内部维护；模型只接收逻辑引用和经过筛选的上下文。

### 2.3 前端运行时与交互

- 修复 SB3 备份 Blob 到 Uint8Array 的转换，避免空备份导致回滚解析错误。
- 资源和程序执行循环只在创建备份前检查旧快照，避免合法的 revision 增长触发误回滚。
- 恢复菜单型输入的 shadow 编译、变量/列表/广播字段类型和广播变量安装时序。
- 恢复 AI 写积木的模型/思考等级选项、计划复用和紧凑折叠布局；使用现有图标体系，不恢复已明确撤回的 App.vue / local-ui.css 临时侧栏改动。
- 恢复画布图层边缘/中心吸附、对齐辅助线及对应测试；保持吸附阈值按屏幕像素换算。
- 不实现文档明确列为未支持的删除角色 VM 操作，不把真实 key 加入版本控制。
