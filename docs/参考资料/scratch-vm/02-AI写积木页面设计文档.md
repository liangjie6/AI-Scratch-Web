## 0. 已确认的产品决策（提问记录）

| 决策点 | 结论 |
| --- | --- |
| 生成基线 | 两种模式可选：默认"从新项目生成"，可切"在当前项目上增量生成" |
| 计划确认 | 无"计划确认"步骤，仅**生图前弹确认** |
| 实时展现 | AI 写成积木后交给 VM 解析，VM 在积木区自动生成积木；**分批注入内容**，不自动运行演示 |

| 撤销粒度 | 模块级独立撤销 + 会话级回退 |
| 素材缺失 | 内置库无匹配且用户拒绝生成时：跳过该素材项，继续其他模块 |
| 上下文 | 自动压缩摘要（每轮结束后固化项目结构+已执行模块结果，裁剪早期消息） |
| 文档位置 | 全部归纳于 `docs/参考资料/scratch-vm/` |

## 1. Design Read（设计读法）

> **Reading this as**: 少儿编程 Scratch 编辑器内的**创作型工具侧边面板**（专为 5-12 岁孩子与家长/教师），语言基调为"Scratch 视觉基因 + Apple 式克制的工具质感"，本次属于 **redesign overhaul**（重构信息架构，保留品牌 accent 与桌面编辑器的熟悉感），不套用 landing page 规则（hero、营销分区不适用）。
>
> **三旋钮**：`DESIGN_VARIANCE: 5`（工具面板求稳定一致，但用"注入高亮/模块流"制造节奏变化）｜`MOTION_INTENSITY: 4`（流体 CSS，仅状态转换与注入反馈）｜`VISUAL_DENSITY: 5`（每日工具密度，屏宽 400px 下信息分层清晰）。

说明：design-taste-frontend 主要面向 landing/portfolio；本面板属于"产品工具面板"（其章节 13 判定为部分超纲）。本篇只沿用其中适用于工具面板的部分：现状审计、防 AI 味、状态完整（loading/empty/error）、对比度与无障碍、禁止 em-dash 与装饰性微文案；不套用 hero/logo 墙/bento 等营销结构。

## 2. 现状审计（Audit，Redesign Protocol 11.B）

### 2.1 现状构成（`frontend/src/ai-blocks/AiBlocksPanel.vue` + `src/styles/ai-blocks.css`）

| 区域 | 现状 |
| --- | --- |
| 顶栏 | 标题 + 历史/新建按钮 |
| 历史抽屉 | 会话列表（含角色/舞台、目标名、时间） |
| 模式区 | 作用范围卡（当前角色/整个项目）+ 模式卡（修改当前代码/旁路新增/清空重写），以 3 等分形式压在头部下方 |
| 聊天流 | 用户/助手消息气泡；助手消息内含"阶段标题+进度条+计划列表+推理折叠" |
| 独立视图 | chat / streaming / review / preparing / committing 五态整页切换 |
| 资源审核 | 全屏覆盖层 ResourcePlanReview + Scratch 内置库选择器 |
| 结果区 | 生成完成后出现"运行查看 / 撤销生成"按钮 |
| 输入区 | 文本域 + 思考开关/强度/模型三档 + 发送按钮 |

### 2.2 保留项（品牌资产与有效模式）

- 聊天流式体验与"需求/计划/进度"渐进展示（有效，保留并强化）。
- Scratch 内置库优先 + 资源审核（改造为模块卡内联后保留通道）。
- 思考/模型档位、历史会话、撤销（保留，位置调整）。
- 品牌 accent 绿 `#2f7865` / `#276452`、浅底 `#eef6f3` / `#e8f4f0`、中性 `--surface/--line/--muted/--ink`（作为 tokens 基底保留）。

### 2.3 退役项（AI 味与体验断点）

1. **微缩字号 9-11px** 全局铺开：实际易读性差、不适合儿童用户。重建字阶基线 ≥12.5px。
2. **五态整页跳变**（chat→streaming→review→preparing→committing）：执行状态被切成不同"页面"，用户失去上下文。改为**单一连续会话流**，执行过程作为消息卡进入流内。
3. **用户气泡用紫色**（`#f2eef9`/`#5b3c9b`）：双 accent 违反一致性锁定，且紫色是 AI 产品惯性色。改为中性深色气泡（仅保留一个品牌绿 accent）。
4. **无模块级状态可视化**：失败/重试/跳过无指定表达；模块间依赖不可见。引入"模块流水线卡"。
5. **错误无闭环**：错误只有文案，无"带原因重试"入口，与本次"3 次重试后停止"策略不符。
6. **模式卡 3 等分 + 范围卡压头部**：与"连续对话"新 IA 冲突。改为**输入区上方的紧凑选择条**（chip 化）。
7. **装饰性**：进度条无背景 track、工作点动画重复度过高；统一为"状态点 + 单点环形"。

## 3. 信息架构（单一连续会话）

```
┌────────────────────────────────────────────────┐
│ 顶栏  AI 写积木  ·  基线: 新项目▾  │ 历史  ＋   │
├────────────────────────────────────────────────┤
│ 上下文条  目标: 整个项目  ·  素材: 内置优先      │
│           积木: 6 块  ·  角色: Pico, Star      │
├────────────────────────────────────────────────┤
│ 聊 天 流（唯一滚动区）                          │
│  ┌ 用户消息                                    │
│  ├ 助手消息（文字流式）                         │
│  ├ [模块流水线卡 M1-M6]  ◀ 本次核心新增         │
│  │   M1 背景 Stars      ✓ 已导入               │
│  │   M2 删除默认角色    ✓ 已删除               │
│  │   M3 导入 Pico       ✓ 已导入               │
│  │   M4 导入 Star       ✓ 已导入               │
│  │   M5 Pico 脚本       ● 第2次尝试 0.2s…      │
│  │   M6 Star 脚本       ○ 等待中               │
│  │        └ 展开: 计划 / 错误原因 / 重试/撤销   │
│  ├ [素材卡] Pico(内置) · Star(内置) · Stars(背景)│
│  ├ 助手总结 + [运行查看] [撤销此模块▾] [回到会话前]│
│  └ [失败卡] M5 第3次失败 · 已停止 · [重试][继续对话]│
├────────────────────────────────────────────────┤
│ 输入区  描述要做的功能…        [思考] [模型▾] [↗] │
│        基准 chip: ◉新项目  ○当前项目  (流水执行中)│
└────────────────────────────────────────────────┘
        └── 右邻：Scratch 编辑器（注入即所见，无遮罩）
```

设计原则：

1. **会话即主容器**：所有状态（流式、执行、确认、失败、完成、撤销）都以"消息卡"身份出现在同一条流里，永不整页跳转。
2. **模块流水线卡是执行期的"唯一主角"**：一个卡承载一次规划的全部模块及其状态；后续对话追加的新模块以**新卡**接入，历史卡保持可展开。
3. **编辑器永远可见**：面板为侧边栏（现状 400px，`min(400px, 100vw)`），注入产生的角色/背景/积木直接在右邻编辑器出现，面板不遮挡。

## 4. 核心交互流程

### 4.1 新建项目生成（用户示例走查）

1. 用户输入："（整个项目）删除默认角色小猫，添加角色 Pico 和 Star；添加背景 Stars；Pico 在左下角；点绿旗等 1 秒后舞台上出现 1-10 随机颗星星一字排开；Pico 询问"请问天上有几颗星星？"，回答正确说"正确"2 秒，否则说"错误"2 秒"。
2. 默认基线"新项目"：**此刻即锁定**并提示"将于新项目中生成（当前项目内容不会丢失）"；若切"当前项目"则提示覆盖风险。
3. 立即流式生成规划 → 流出"模块流水线卡"（M1 背景 Stars / M2 删除默认角色 / M3 导入 Pico / M4 导入 Star / M5 Pico 脚本 / M6 Star 脚本）。无确认步骤（用户决策）。
4. 执行引擎按拓扑序跑：每模块卡就位后立即注入（背景出现在舞台、角色出现在列表、积木出现在编辑区），状态点自"等待中"变"执行中"变"完成"。
5. M5/M6 是脚本模块：生成 ProgramIR → 编译 → VM 注入 → 积木区出现 Pico/Star 脚本；不自动运行。
6. 完成：全体 ✓ + 助手总结（实际名称、素材来源、模块清单）+ 操作区（运行查看 / 撤销此模块 / 回到会话前）。

### 4.2 生图确认（唯一人工确认点）

- 触发：某素材项在内置库无匹配（或用户明确要求生成）。
- 呈现：**该模块行展开为确认面板**：原因 + 素材名 + 提示词 + 尺寸 + 标签 + [使用内置素材] [生成图像] [跳过]。
- 确认后：生成图像 → 存素材库 → 转入 Commit；"跳过"：该素材项标记 skipped（琥珀色），继续后续模块（用户决策）。

### 4.3 失败重试与停止

- 模块失败 → 行内红条显示"第 n/3 次" + 错误原因（可展开原文）→ 自动带原因重试（复用后端 repair 通道）。
- 3 次后：流水线**停止**，之前成功模块全部保留；卡折叠为"失败卡"：原因 + [重试] [继续对话]。
- 用户可点"重试"（仅重该模块）或直接在输入框续聊（"把 Pico 移到右上角" / "我刚刚裁剪了星星，用新的"）。

### 4.4 继续对话修改（类 agent）

- 每条新用户消息都会带上"会话摘要 + 当前项目快照"（自动压缩，见 4.6）。
- 若新需求只涉及已存在目标：规划输出"追加模块卡"（如 M7 调整 Pico 位置），与前序卡并列，不覆盖。
- 若新需求是纠错（"星星没有一字排开"）：先查项目现状（读 VM 块图）再生成"修复卡"，注明"将覆盖 M6 的部分脚本"（破坏性元数据可视化）。

### 4.5 撤销

- 模块级：任何"完成"模块可展开 [撤销此模块]（逆操作日志，O(模块规模)）。
- 会话级：最末操作区 [回到会话前]（会话启动时的 SB3 备份，一次性还原）。
- 撤销按钮在 revision 变化时禁用（用户手动编辑后拒绝静默覆盖，沿用现状）。

### 4.6 上下文自动压缩

- 每轮结束后生成一页**会话纪要**（追加为系统消息，旧消息裁剪）：
```
[会话纪要 vN]
项目：<名>，基线：新项目/当前项目，revision：<r>
目标：[Stage:背景 Stars, 当前 n] [Pico: 造型1, 脚本: 绿旗-等待-克隆星星-询问] [Star: 脚本: 克隆体-排列]
共享量：<列表>
已执行模块：M1..M6（结果摘要，含 retry 计数）
未完成：无/失败项 M5（原因摘要）
用户最近需求：<一句摘要>
```
- 纪要上限 ~1.2k 字符；旧消息按"纪要 + 最近 4 条"保留。
- 副作用提示：早期模糊表述在压缩后丢失细节（如用户改口的历史歧义），面板在纪要卡上提供"查看原始消息"回溯。

## 5. 界面规格（逐组件）

### 5.1 顶栏（58px 保持）
标题 + 基线选择（pill 下拉：新项目/当前项目，新项目默认）+ [历史] [+ 新会话]。基线切换仅允许在"无进行中执行"时。

### 5.2 上下文条（新增，34px，常显）
一行胶囊摘要：`整个项目 · 角色 2 · 背景 1 · 脚本 6 段 · rev 12`。数据源自会话纪要；点击展开"项目清单"（目标/变量/素材明细）。

### 5.3 模块流水线卡（核心组件）

| 部分 | 规格 |
| --- | --- |
| 头部 | 标题"生成计划" + 模块计数（已完成 2/6）+ 收起/展开 |
| 模块行 | 左侧状态点（待执行 ○灰 / 执行中 ⟳绿 / 完成 ✓绿 / 失败 ✕红 / 重试中 ◐琥珀 n/3 / 跳过 ⤼琥珀）、主标题（动词+对象）、右侧副信息（素材来源/尝试次数） |
| 行展开 | 计划摘要、依赖说明、错误原因（mono 字体块）、操作按钮（重试/撤销/查看注入） |
| 完成态 | 整卡转为可折叠"已完成"摘要，供后续对话引用 |

状态机：`idle → running → done | failed(retry:1..3) → stopped | skipped`。任意模块 failed 且未到 3 次时自动重试，无需用户介入；到 3 次整卡转 stopped。

### 5.4 素材卡
注入完成的素材（内置/生成）以横向缩略卡呈现：图片 + 名称 + 来源徽标（内置/生成）+ [查看]。生成素材另注标签；点击卡片定位编辑器对应角色/背景。

### 5.5 错误卡（失败停止态）
红色单卡，含：模块名、第 3/3 次、错误原因（可展开全文）、[重试该模块]（主按钮）与[继续对话]（次按钮）。文案示例（见第 8 章文案表）。

### 5.6 输入区（composer）
- 文本域（3-8 行自适应，Enter 发送，Shift+Enter 换行）。
- 上方 chip 行：基线（新项目/当前项目）+ 范围（整个项目/当前角色，项目模式默认）+ 素材策略（内置优先/仅已有/允许生成）。
- 右侧控制：思考开关+强度、模型档位、发送按钮（28-36px 触控区）。
- 流水线执行中：输入框仍然可用（允许"提前排队"下一指令？不：首版禁用发送，仅允许"打断"按钮含"继续/停止"；保留为 Phase 2 增强）。
- 执行中提示条：`第 2 个模块执行中（1/3 重试）…` + [停止]。

### 5.7 生图确认面
模块行内展开（不弹全屏）：原因文案、素材名、提示词（可编辑）、尺寸固定、标签 chips、[用内置素材] [生成图像]（主） [跳过]。确认通过前绝不生图。

### 5.8 历史抽屉
复用现状；条目增加"已完成模块数"与"最后状态"小标；会话恢复后滚动到对应流水线卡。

### 5.9 状态齐全性（防跳变）
- Loading：模块行以骨架条（匹配行高）占位。
- Empty：初始态给 2 个示例任务（含本示例"星星问答"）一键填充。
- Error：见 5.5；网络中断给"重连并续跑"（后端断线重连沿用请求 ID 语义）。
- Partial：完成但含 skipped 的摘要行（琥珀）。

## 6. 视觉语言

### 6.1 色彩（单 accent 锁定）
```
--accent:        #2f7865  （品牌绿，唯一行为色）
--accent-strong: #276452
--accent-soft:   #e8f4f0
--accent-line:   #bfd1cc
--ink:           #1c2b27
--muted:         #5d6d68
--surface:       #ffffff
--surface-2:     #f6f9f8
--line:          #e2e9e6
--danger:        #a63232  / 底 #fff1f1
--warn:          #8a5a12  / 底 #fff4e0  （重试/跳过）
--ok:            #2f7865  / 底 #e8f4f0
```
- 用户气泡：改为 `--ink` 深底白字（去掉紫色）。
- 品牌绿仅用于：主按钮、状态点、链接、选中态、注入高亮。

### 6.2 字阶
基线 13px（正文可读），标题 14/15px，辅助 11.5px；行高 1.55；中文优先系统字体（PingFang SC/Microsoft YaHei）＋数字用 tabular nums。**全局下限 11px**（比现状 9px 提高可读性）。

### 6.3 圆角/间距/阴影
- 统一体系：卡片 8px / 输入与 chip 6px / 按钮胶囊 999px。一套规则写进设计常量。
- 间距 4px 网格；卡内 12px，模块行间 8px。
- 阴影仅用于悬浮层（确认面/历史抽屉），用绿色系灰（`rgba(28,43,39,.12)`），禁纯黑。

### 6.4 图标
沿用 lucide，stroke 2.0，尺寸 14/16/20；状态点用 CSS 圆点而非图标（除 ✓✕◐ 用对勾/叉/半圆）。

## 7. 动效（MOTION 4，全部可降级）

| 场景 | 动效 | 时长/曲线 | 降级 |
| --- | --- | --- | --- |
| 模块状态转换 | 状态点 scale 弹出 + 行背景轻扫 | 180ms spring(100,20) | 静态样式差 |
| 注入完成 | 编辑器侧"新对象"短暂 ring 高亮（角色列表项/背景条） | 600ms 一次 | 撤去 ring |
| 重试计数 | 琥珀脉冲点（非无限循环，最多 3 次） | 900ms ×3 | 静态"2/3" |
| 消息进入 | y+8 fade，仅首屏 3 条 | 240ms ease-out | 无 |
| 进度条 | 无 background track，白色轨道 + 绿色填充 | 120ms linear | 不动画 |

禁止：无限循环微动效、霓虹发光、滚动劫持、视差。

## 9. 无障碍与响应式

- 对比度（实测 WCAG）：正文 `--ink` #1c2b27 on `--surface` #ffffff 为 14.74:1；次要绿 #276452 on 白 为 6.93:1；主绿 #2f7865 on 白 为 5.26:1；琥珀文字 #8a5a12 on #fff4e0 为 5.42:1；危险红 #a63232 on #fff1f1 为 6.12:1；次要文字 #5d6d68 on 白 为 5.45:1。全部 ≥4.5:1。
- 语义：模块流水线卡用 `role="list"` 列表 + 每行 `aria-label`（含状态）；聊天区 `aria-live="polite"`（执行状态用 assertive 仅首次）。
- 键盘：模块行可 Tab 聚焦并 Enter 展开；确认面 Esc 关闭；发送 Enter/Shift+Enter 注明提示。
- 触控：交互目标 ≥36px；面板宽度 400px，`max-width: 100dvw`。
- 响应式：≤700px 面板占宽减小、上下文条隐藏为点击展开；≤420px 全宽（现状已定，保留）。
- 多动效属性：全局 `@media (prefers-reduced-motion: reduce)` 关闭除状态点外全部动画。

## 12. 设计验收标准（实现落地时核对）

1. 一次自然语言请求（样例"星空数星星"）能完成：规划流出 → 六模块依次执行 → 编辑器内背景/角色/积木分批出现 → 总结出现，全程无整页跳变。
2. 生图确认只出现在"内置库无匹配"时；确认前 0 次生图请求。
3. 人为注入脚本错误（如 M5 编译失败）→ 显示"第 n/3 次"→ 自动重试 ≤3 → 停止时 M1-M4 完好可展开撤销。
4. 继续对话"把 Pico 移到右上角"→ 追加 M7 卡，不改动 M1-M6。
5. "撤销此模块"只回退该模块；"回到会话前"回退到会话开始。
6. 刷新/断线后会话可恢复（纪要 + 项目快照重建）；用户手动编辑后撤销按钮置灰。
7. 所有可见文案无破折号、无糊化词；字号 >11px；对比度抽查通过。
