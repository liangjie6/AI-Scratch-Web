# AI-Scratch-web 无边画布功能设计

> 文档状态：Draft v1.0  
> 适用项目：AI-Scratch-web  
> 目标版本：无边画布 MVP  
> 核心场景：AI 角色图去除纯色背景，拆分多个图层，并作为同一 Scratch 角色的多个造型导入

## 1. 背景

当前 AI-Scratch-web 已具备 AI 图片生成、单张图片预览、缩放后导入 Scratch 背景或新角色的基础闭环。现有流程适合单张背景，但无法高质量处理角色素材，主要问题如下：

1. AI 角色图通常带纯色或近似纯色背景，Scratch 本身没有色度抠图能力。
2. AI 可能生成四宫格或多动作雪碧图，Scratch 不能在导入前交互式裁切和拆分。
3. 现有导入逻辑只创建一个角色造型，无法把多个区域一次转换为同一角色的多个造型。
4. 用户无法修复残留背景、边缘杂色、透明像素和局部瑕疵。
5. 图片处理没有图层、历史记录和中间状态，误操作后难以恢复。

因此需要在 AI 生成结果和 Scratch VM 之间增加一个独立的无边画布编辑工作区。该工作区负责图片准备，不替代 Scratch 的造型编辑器，也不直接修改 Scratch VM 内部对象。

## 2. 产品目标

### 2.1 核心目标

用户能够完成以下闭环：

1. 从 AI 生成结果、磁盘、拖放或剪贴板载入图片。
2. 在无边画布中平移、缩放、裁剪和调整图片。
3. 使用色度抠图去除纯色或近似纯色背景，并精修透明边缘。
4. 使用选择工具框选雪碧图中的一个角色动作。
5. 将选区复制或剪切为独立图层，重复得到多个动作图层。
6. 调整图层名称、顺序、画框和旋转中心。
7. 将多个图层导出为独立 PNG，或一次导入为同一个 Scratch 角色的多个造型。
8. 所有画布编辑操作支持撤销、重做和本地恢复。

### 2.2 设计原则

- **无损优先**：原始图片默认保留，裁剪和色度抠图优先以画框、参数或独立位图 revision 保存。
- **图层与造型解耦**：图层负责编辑和合成，造型队列负责 Scratch 导出，不能依靠“当前可见图层”隐式判断导出内容。
- **Scratch VM 是项目事实来源**：画布只生成标准 PNG 和造型元数据，通过统一适配器进入 VM。
- **像素结果可预测**：导出结果必须与画布预览一致，不能在导入时再次静默拉伸、裁切或去色。
- **高频流程优先**：四宫格拆分、背景抠除、造型对齐和批量导入应尽量减少重复操作。
- **本地处理**：用户上传图片的编辑、历史和导出默认全部在浏览器本地完成，不上传到额外服务。

## 3. 范围

### 3.1 MVP 范围

- AI 生成结果、PNG、JPEG、WebP 图片导入。
- 角色生成默认请求可选纯色抠图背景，并向画布传递建议取色提示。
- 无边工作区、有限导出画框、平移、缩放和适应视图。
- 矩形选区和交互式裁剪。
- 色度抠图：取色、容差、柔化、相邻背景模式、去色边。
- 像素画笔、铅笔、橡皮擦、油漆桶、吸管。
- 栅格图层的新建、复制、删除、重命名、排序、显隐、锁定、透明度。
- 从当前图层或可见合成复制选区为新图层。
- 图层到造型队列的显式映射。
- 造型名称、顺序、画框、统一尺寸、旋转中心调整。
- 撤销、重做、会话历史、本地自动恢复。
- 合成 PNG、单图层 PNG、批量 PNG ZIP 导出。
- 多图层一次导入为一个 Scratch 新角色的多个造型。

### 3.2 后续增强

- 自动网格拆分助手，支持 2×2、3×3、自定义行列和间距。
- 套索、魔棒、选区羽化、选区扩展和收缩。
- 图层组、图层蒙版、混合模式和调整图层。
- 向当前 Scratch 角色追加或替换造型。
- 标准 sprite3 文件下载。
- 无边画布工程文件导入、导出和多文档管理。
- AI 语义分割、自动识别动作单元格和自动去背景。

### 3.3 非目标

- 完整复刻 Photoshop。
- 矢量路径、文字排版、CMYK、专业色彩管理和印刷输出。
- 动画时间轴或逐帧播放编辑器。
- 云端协作、账号同步或服务器长期保存用户图片。
- 修改 Scratch VM、Scratch Renderer 或 SB3 格式。

## 4. 关键概念

为避免“画布”“裁剪”“图层”“造型”混用，统一定义如下：

| 概念 | 定义 |
| --- | --- |
| 工作区 Workspace | 可无限平移和缩放的编辑空间，不直接决定导出尺寸。 |
| 视口 Viewport | 用户当前看到的屏幕区域，平移和缩放不进入撤销历史。 |
| 文档 Document | 一次图片编辑任务，包括图层、选区、效果、画框和造型队列。 |
| 合成画框 Artboard | 导出整张合成图片时使用的有限矩形。 |
| 图层 Layer | 可独立编辑、显隐、移动和输出的栅格内容。 |
| 选区 Selection | 位于文档坐标中的临时像素范围，不等于图层。 |
| 造型条目 Costume Entry | 引用一个图层及其画框、名称、顺序和旋转中心的 Scratch 导出配置。 |
| 造型画框 Frame | 某个造型最终导出的有限矩形，可包含透明边距。 |
| 旋转中心 Pivot | Scratch costume 的 rotationCenterX 和 rotationCenterY。 |
| 栅格化 Rasterize | 将图层变换、透明度、色度抠图效果和像素内容合成为确定的 PNG 像素。 |

**重要规则：无边的是工作区，不是导出图片。** 每次导出必须使用合成画框或造型画框，否则无法得到确定的 PNG 尺寸。

## 5. 用户入口与页面结构

### 5.1 入口

1. AI 生成结果旁新增“在画布中编辑”。
2. 角色目标生成完成后，将“在画布中编辑”作为主操作；背景仍可保留“直接导入”快捷操作。
3. Scratch 编辑页工具区新增“画布”入口，可上传本地图片开始空白文档。
4. 支持将图片拖入画布、粘贴剪贴板图片。

### 5.2 打开方式

画布采用全屏工作区覆盖在现有应用内，但 ScratchHost 保持挂载，只隐藏视觉内容，不销毁 VM。用户返回 Scratch 时，项目、选中角色和运行状态仍然存在。

不在当前窄 AI 侧栏中嵌入完整画布。像素编辑、图层和造型对齐需要稳定的大视口，强行放入侧栏会降低可用性。

### 5.3 桌面布局

- 顶部：返回 Scratch、文档名、撤销、重做、导入图片、导出、导入 Scratch。
- 左侧：移动/变换、矩形选区、裁剪、色度抠图、画笔、铅笔、橡皮擦、油漆桶、吸管、抓手、缩放工具。
- 中央：无边画布视口、透明棋盘格、选区边界、变换控制柄和旋转中心标记。
- 右侧上部：当前工具属性，例如容差、柔化、画笔大小、比例。
- 右侧下部：两个标签页“图层”和“造型”。
- 底部：缩放比例、光标文档坐标、选区尺寸、当前图层像素尺寸、内存提示。

### 5.4 小屏策略

- 平板横屏：右侧面板改为可收起抽屉，工具栏保持图标模式。
- 手机：允许查看、简单取色抠图、导出和导入 Scratch；复杂像素编辑不作为 MVP 验收主路径。
- 触控支持双指缩放、双指平移和可放大的选区控制柄，不能只依赖鼠标右键或悬停。

## 6. 核心用户流程

### 6.1 四宫格角色雪碧图流程

1. 用户生成或上传一张四宫格角色图。
2. 图片以“原图”图层载入，保持原始像素尺寸，视口自动适应图片。
3. 用户选择色度抠图工具，在背景上取色。
4. 系统实时预览透明结果，用户调整容差、柔化和去色边。
5. 用户确认，色度抠图参数作为图层效果保存。
6. 用户使用矩形选区框选左上角角色。
7. 点击“复制为新图层”或按 Alt+J，新图层自动加入造型队列。
8. 用户依次框选四个角色并复制，得到“造型1”至“造型4”。
9. 原图图层保留但默认不加入造型队列，用户可以隐藏或锁定原图。
10. 在“造型”标签页中调整顺序、名称、统一画框和旋转中心。
11. 用户可预览造型快速切换，检查角色是否跳动、偏移或被裁掉。
12. 点击“导入 Scratch”，系统创建一个新角色，并写入四个 PNG 造型。
13. Scratch 自动选中新角色，当前造型设为第一个造型。
14. 保存 SB3 后，四个造型和透明通道必须完整保留。

### 6.2 普通单图流程

1. 用户上传图片。
2. 通过裁剪设置合成画框。
3. 使用色度抠图和橡皮擦修复背景。
4. 导出透明 PNG，或作为单造型角色导入 Scratch。

### 6.3 自动网格拆分增强流程

用户可输入行数、列数和单元格间距，系统预览网格并一次创建多个图层和造型条目。自动拆分只减少重复框选，不改变手工选区流程，也不能假设所有 AI 雪碧图都有严格等宽网格。

## 7. 功能设计

### 7.1 图像上传与适配

#### 输入来源

- AI 生成结果中的原始 PNG Blob 或 Base64 数据。
- 文件选择器。
- 拖放文件。
- 剪贴板图片粘贴。

#### 支持格式

- MVP：PNG、JPEG、WebP。
- GIF 只读取首帧会造成误解，MVP 直接提示不支持。
- SVG 存在脚本、外链资源和字体差异风险，MVP 不导入。

#### 解码规则

1. 优先对 createImageBitmap 的 imageOrientation 和 colorSpaceConversion 选项做能力检测，再使用显式选项解码；不依赖各浏览器默认值。
2. 不支持相关选项或解码失败时，回退到 HTMLImageElement 加 Canvas，并根据解析出的 EXIF 方向执行一次且仅一次变换。
3. MVP 采用浏览器托管的显示色彩，不宣称完成专业 sRGB 归一化；要求同一浏览器内预览与导出观感一致，并使用 ICC/P3 测试图记录跨浏览器差异。
4. 保留原始宽高、方向、文件名、MIME、来源和导入时间。
5. 使用 Object URL 时在资源释放后调用 revokeObjectURL。
6. 禁止直接绘制未经同源处理的远程 URL，避免 Canvas 被污染后无法导出。
7. 使用 EXIF 方向 2 至 8 的 fixture 验证方向不会遗漏或重复应用。

#### 尺寸限制

- 产品最大上限：单边 8192 像素、单图 3200 万像素；这些是拒绝阈值，不是浏览器一定能成功分配的保证。
- 手机软上限：单边 4096 像素、单图 1200 万像素；超过后默认建议降采样。
- 单文件建议上限：50 MB，但准入同时按解码后的 RGBA 内存估算，不能只看压缩文件大小。
- 解码、离屏 Canvas 和导出前分别做实际分配探测，并捕获分配失败、getImageData 失败和 toBlob 返回 null。
- 超限或运行时分配失败时显示原尺寸、预计内存和建议尺寸，由用户确认后等比降采样；不能静默缩小。

#### 初始适配

- 默认保留 100% 原始像素，不自动改写图片尺寸。
- 合成画框初始等于图片边界。
- 图片中心放置于文档原点附近，视口执行“适应内容”。
- “适应视图”只改变视口，不改变图层像素。
- AI 生成结果进入画布时必须使用模型原图，不能先按 Scratch 舞台尺寸拉伸，否则四宫格和边缘细节会被破坏。

#### AI 角色生成协同

当生成目标为角色时，生成面板默认启用“纯色抠图背景”，提供亮绿、亮蓝、洋红和自定义色块。后端提示词要求背景颜色均匀、无渐变、无纹理、无投影，并要求角色或多个动作之间留出明确间距。背景目标不启用该设置。

生成响应可增加不参与 Scratch 资产的处理提示：

    processing_hints: {
      background_mode: 'solid';
      suggested_key_color: '#00FF00';
      sheet_layout?: {columns: number; rows: number};
    }

suggested_key_color 只表示请求给模型的目标颜色，不能被当成图片真实像素。画布可用它预填色度抠图色块，但用户取色后必须以实际采样值为准。模型若产生阴影、渐变或颜色偏差，仍通过容差、柔化、相邻背景模式和像素工具修正。

画布数据模型不依赖固定 1×1 或 2×2。即使当前生成接口只返回 1×1，上传的四宫格和后续 sheet_layout 扩展也使用同一拆层流程。

### 7.2 无边画布与导航

#### 坐标系统

- 屏幕坐标：DOM 像素。
- 视口坐标：考虑设备像素比后的显示坐标。
- 文档坐标：稳定的世界坐标，图层、选区和画框均存储于此。
- 图层局部坐标：相对于图层位图左上角的像素坐标。

所有交互必须通过统一矩阵完成坐标转换，禁止在不同工具中各自计算缩放偏移。

#### 导航操作

- 鼠标滚轮：缩放，以光标位置为缩放中心。
- 空格加拖动或抓手工具：平移。
- 双击抓手：适应全部内容。
- 100%：一个源像素对应一个 CSS 像素，并考虑设备像素比。
- 缩放范围：5% 至 3200%。
- 800% 以上可显示像素网格，像素网格不参与导出。

#### 渲染要求

- 视口外内容应裁剪或缓存，避免每帧重绘全部像素。
- 平移和缩放只重绘显示结果，不修改位图。
- 透明区域使用中性棋盘格，工作区背景与透明棋盘格必须有明确边界。

### 7.3 交互式裁剪

裁剪和选区是两个工具：

- 裁剪：调整合成画框或当前造型画框。
- 选区：选择像素并复制、剪切、删除或移动。

#### 裁剪能力

- 自由比例。
- 1:1、4:3、16:9、Scratch 舞台 480:360。
- 数值输入 X、Y、宽、高。
- 控制柄缩放，Alt 从中心缩放，Shift 锁定比例。
- 画框外区域半透明遮罩。
- 确认裁剪默认只更新画框，不删除框外源像素。
- 提供“删除框外像素”显式操作，并进入历史记录。

#### 裁剪约束

- 最小导出尺寸 1×1。
- 超过导出上限时提示，不在确认后才失败。
- 裁剪时允许画框超出图层边界，超出部分导出为透明像素。

### 7.4 选择工具

#### MVP 选区能力

- 矩形选区。
- 新建、追加、减去、相交模式。
- 移动选区边界。
- 全选、取消选择、反选。
- 删除选区像素。
- 复制为新图层。
- 剪切为新图层。
- 复制来源可选“当前图层”或“可见内容合并”；剪切来源只允许当前活动图层。

#### 复制为新图层

默认快捷键 Alt+J，行为如下：

1. 获取选区在文档坐标中的边界。
2. 读取当前图层应用变换、透明度和色度抠图效果后的最终像素。
3. 选区外像素设为透明。
4. 新图层位图尺寸等于选区边界，保留其在工作区中的视觉位置。
5. 新图层不继承原图层的色度抠图效果，因为结果已被栅格化到 Alpha。
6. 新图层名称按“造型1、造型2”递增，并默认加入造型队列。
7. 新造型画框等于本次选区矩形，不按非透明像素自动收紧。
8. 原图层保持不变；使用“剪切为新图层”时才清除符合下述约束的源像素。
9. 整个操作作为一个历史事务撤销或重做，并记录操作前后的选区快照。

保留选择矩形作为造型画框非常重要。若直接按非透明像素收紧，不同动作的 PNG 尺寸和旋转中心会变化，Scratch 切换造型时容易出现跳动。

#### 剪切约束

- 复制始终通过文档坐标栅格化，支持任意可逆图层变换和“可见内容合并”。
- MVP 的剪切只作用于一个未锁定的活动图层，不提供“剪切可见内容合并”。
- 活动图层必须只有平移变换；存在旋转、斜切或未应用缩放时，先提示用户“应用变换”，不能猜测应清除哪些源像素。
- 清除操作将文档选区通过逆平移映射到图层局部整数像素，并把对应源 Alpha 设为 0。
- 若图层存在未栅格化色度抠图效果，剪切前先按像素编辑规则处理效果。

#### 图层移动与变换

移动/变换工具作用于活动图层或多选图层，不修改像素选区。它提供边界框、八个缩放控制柄和旋转控制柄，并支持数值输入 X、Y、宽、高和角度。

- 移动、缩放和旋转先更新图层变换矩阵，不立即重采样源位图。
- 拖动期间只显示预览，指针抬起后生成一个历史条目。
- Shift 锁定宽高比，Alt 以中心为基准，方向键进行 1 文档像素微移。
- 支持吸附到合成画框边缘、中心线、其他图层边界和造型旋转中心；按住 Ctrl 临时关闭吸附。
- 普通图片使用高质量插值，像素画模式可选择 nearest-neighbor，导出器必须复用相同采样策略。
- “应用变换”是显式栅格化操作，完成后重置矩阵并进入历史；在此之前始终保留原始位图。

### 7.5 色度抠图

#### 工具参数

- 目标颜色：吸管取色，显示颜色色块和数值。
- 容差：控制与目标色相近的像素范围。
- 柔化：控制边缘 Alpha 过渡宽度。
- 作用模式：相邻背景、全图同色。
- 去色边：减少半透明边缘上的背景色溢出。
- 反选：保留背景色、移除其他颜色，用于特殊素材。
- 预览：透明结果、Alpha 黑白蒙版、红色覆盖三种模式。

#### 默认模式

默认使用“相邻背景”，只移除与目标颜色相近且连通的区域。这样可以减少角色衣服、眼睛或道具中同色像素被误删的概率。

“全图同色”适合纯色摄影棚背景或四宫格单元之间不连通的背景，但必须由用户主动选择。

#### 相邻背景种子与连通规则

- 种子模式分为“图像边缘”和“点击种子”，默认使用图像边缘。
- 图像边缘模式把四条边上颜色距离不大于外部阈值且源 Alpha 大于 0 的像素作为种子，所有种子结果取并集。
- 点击种子模式支持一个或多个点击点；种子保存为图层局部整数像素坐标，图层移动和缩放不改变其含义。
- 默认采用 8 邻域连通，后续可提供 4 邻域高级选项；同一文档必须固定该参数以保证恢复结果确定。
- 泛洪只进入颜色距离不大于外部阈值且源 Alpha 大于 0 的像素。成员集合确定后，再依据内部阈值、外部阈值和柔化计算最终 Alpha。
- 全图同色模式不读取种子点。

#### Alpha 计算

对每个候选像素计算其与目标颜色的归一化颜色距离 d：

- d 小于内部阈值时，输出 Alpha 为 0。
- d 大于外部阈值时，保留原 Alpha。
- 中间区间使用 smoothstep 生成连续 Alpha，避免锯齿硬边。
- 最终 Alpha 等于原 Alpha 乘以抠图 Alpha。

颜色距离实现第一版使用线性 RGB 归一化距离，Worker 中保留替换为 Lab 色差的边界。不能直接比较十六进制字符串或仅比较绿色通道。

#### 去色边

对部分透明的边缘像素降低目标背景色的分量，并使用邻近不透明前景色进行有限校正。去色边只作用于过渡区域，不能改变完全不透明的主体颜色。

#### 非破坏性规则

- 调节参数期间只更新预览，并以 effect revision 丢弃迟到的 Worker 结果。
- 用户点击“应用”后，将目标颜色、容差、柔化、种子模式、种子点、连通规则和去色边保存为图层效果。
- 再次编辑效果时从该图层当前的源位图重新计算，不对上一次效果输出继续叠加，避免边缘质量逐步下降。
- 用户可选择“栅格化效果”，将当前结果写入新的位图 revision 并移除效果参数；原图图层仍保留初始导入像素。
- 图层存在未栅格化效果时，画笔、铅笔、橡皮擦、填充、清除和剪切默认先弹出“栅格化效果并继续”。确认后，栅格化与随后的像素操作组成一个历史事务；取消则不修改图层。
- MVP 不维护一套隐式效果蒙版和一套独立手绘蒙版，避免重新调节抠图时覆盖或改变用户已看到的像素修补。

### 7.6 像素级编辑

#### MVP 工具

| 工具 | 行为 |
| --- | --- |
| 画笔 | 支持大小、硬度、不透明度和颜色，连续插值笔迹。 |
| 铅笔 | 1 像素硬边为主，不进行抗锯齿，适合像素画。 |
| 橡皮擦 | 修改 Alpha，不用背景色覆盖。 |
| 油漆桶 | 基于容差填充相邻区域，透明区域也可填充。 |
| 吸管 | 读取最终合成颜色或当前图层原始颜色。 |
| 清除 | 将选区或当前图层像素设为透明。 |

#### 像素编辑规则

- 默认只修改当前活动栅格图层的源位图 revision。
- 锁定图层、隐藏图层或无活动图层时禁止绘制，并给出明确状态。
- 图层存在未应用几何变换时，指针通过逆矩阵映射到局部像素；图层存在色度抠图效果时必须先按上述规则栅格化。
- 橡皮擦和清除直接修改源 Alpha，不维护文档中未声明的隐藏蒙版。
- 一次按下到抬起视为一个笔画和一个撤销步骤。
- 快速指针事件使用插值补点，避免高速拖动出现断线。
- 高倍缩放下可启用像素吸附。

### 7.7 图层系统

#### 图层类型

MVP 只提供栅格图层。色度抠图作为栅格图层效果存在，不新增独立调整图层。后续可扩展图层组、蒙版和调整图层。

#### 图层属性

- 唯一 ID。
- 名称。
- 缩略图。
- 可见性。
- 锁定状态。
- 不透明度。
- 混合模式，MVP 固定为 Normal。
- 位图资源引用。
- 文档坐标中的变换矩阵。
- 像素边界。
- 可选色度抠图效果。
- 创建时间和更新时间。

#### 图层面板操作

- 单选和 Shift 多选。
- 拖放排序。
- 新建空白图层。
- 复制图层。
- 删除图层。
- 重命名。
- 合并所选图层。
- 向下合并。
- 显示、隐藏。
- 锁定、解锁。
- 修改透明度。
- 加入或移出造型队列。

#### 图层与造型的关系

图层栈的主要职责是编辑合成，造型队列的主要职责是 Scratch 输出。二者不能完全等同，规则如下：

1. 一个造型条目在 MVP 中引用一个栅格图层。
2. 一个图层可以不进入造型队列，例如原始四宫格底图、参考线和辅助图层。
3. 图层隐藏不自动移出造型队列，避免用户为了查看其他内容而意外改变导出结果。
4. 隐藏但仍在造型队列中的图层会在导出前显示警告，由用户决定导出或移出。
5. 造型顺序在“造型”标签页中独立显示和拖放，默认按创建顺序排列。
6. 删除被引用图层时，必须同时删除对应造型条目，并允许整体撤销。
7. 重命名图层时，尚未手动改名的造型名称同步更新；手动命名后不再自动覆盖。

#### 原图保护

从 AI 或文件导入的第一个图层命名为“原图”，默认锁定、默认不加入造型队列。用户可以解锁编辑，但系统应优先鼓励复制和无损处理。

### 7.8 造型队列与对齐

这是图层导入 Scratch 的关键中间层。

#### 造型条目属性

- ID。
- 引用的 layerId。
- Scratch 造型名称。
- 导出顺序。
- 造型画框 frameRect。
- 旋转中心 pivotX、pivotY，坐标相对于造型画框左上角。
- 对齐方式：中心、底部中心、自定义。
- 输出缩放比例。
- 导出状态和校验错误。

#### 画框模式

- **保留选择框**：默认。每次复制选区时使用原选择矩形，适合规则雪碧图。
- **紧贴内容**：按非透明像素边界裁切，文件更小，但可能造成造型切换跳动。
- **统一画框**：将多个造型扩展到相同宽高，透明填充空白区域，推荐用于动画。

“统一画框”不能简单把所有内容居中。系统应允许用户选择中心对齐或底部中心对齐。角色走路、跳跃等动作推荐底部中心对齐，使脚底位置稳定。

#### 旋转中心

- 默认位于画框中心。
- 角色动画可切换为底部中心。
- 画布上显示十字标记，可拖动调整。
- 支持“应用到所有造型”。
- 预览器快速切换造型时固定旋转中心位置，用户可直观看到抖动。
- 自定义中心允许位于画框外，不自动夹紧；界面显示警告，自动角色大小使用中心到四边的最大跨度计算。非有限值或超出实现安全范围时才阻止导出。

#### Scratch 位图坐标契约

当前锁定的 @scratch/scratch-vm 15.0.1 以 bitmapResolution=2 作为 Scratch 3 位图造型的标准。若传入 bitmapResolution=1，VM 会将图片宽高和旋转中心放大 2 倍、重写 PNG Asset，并把元数据改为 2。为避免隐藏转换，画布导出的角色造型统一使用 bitmapResolution=2。

必须区分三类坐标：

- 文档像素：无边画布和造型画框使用的坐标。
- Asset 像素：导出 PNG 的真实像素，rotationCenterX 和 rotationCenterY 按此坐标写入 costume JSON。
- Scratch 逻辑单位：舞台上的尺寸，等于 Asset 像素除以 bitmapResolution。

换算公式如下：

    assetWidth = round(frameWidth * exportScale)
    assetHeight = round(frameHeight * exportScale)
    rotationCenterX = (pivotDocumentX - frameX) * exportScale
    rotationCenterY = (pivotDocumentY - frameY) * exportScale
    logicalWidth = assetWidth / 2
    logicalHeight = assetHeight / 2
    logicalPivotX = rotationCenterX / 2
    logicalPivotY = rotationCenterY / 2

exportScale 默认 1，表示保留画框中的源像素密度；如需要一个文档像素对应一个 Scratch 逻辑单位，可显式使用 exportScale=2。Asset 宽高使用 round 后的正整数，有限的 rotationCenterX/Y 保留小数，不做隐式取整，预览与 VM 均使用同一浮点值。若导出时改变画框或缩放，必须先生成最终 Asset 尺寸，再换算旋转中心，禁止先计算中心后裁透明边。分数 exportScale、分数画框原点和分数 pivot 必须有 fixture。

#### 单个造型栅格化顺序

1. 校验造型条目、引用图层、画框、缩放和旋转中心。
2. 按画框乘以 exportScale 创建透明离屏 Canvas，输出宽高取正整数。
3. 将引用图层从文档坐标变换到画框局部坐标。
4. 依次应用源 Alpha、像素编辑结果、色度抠图效果和图层透明度。
5. 只绘制该造型引用的图层，不混入其他可见图层，并裁掉画框外像素。
6. 计算 Asset 像素坐标中的旋转中心，以 bitmapResolution=2 编码 PNG Blob。
7. 对编码后的 PNG 再次校验宽高、非空 Alpha 和中心范围，生成 CostumeExport。
8. Scratch 导入后校验实际 costume 的 bitmapResolution、Asset 像素尺寸和旋转中心，不以 assetId 或 PNG 压缩字节完全相同作为正确性判断。

编辑器中的图层可见性只影响画布合成预览。造型条目的 enabled 才决定是否导出；被隐藏但已启用的造型在导出前警告，用户确认后仍按该图层内容栅格化。

### 7.9 历史状态管理

#### 历史范围

进入历史：

- 图层增删、重命名、排序、显隐、锁定和透明度。
- 位图绘制、擦除、填充和清除。
- 色度抠图应用、修改、关闭和栅格化。
- 选区复制或剪切为图层。
- 裁剪画框、移动和变换图层。
- 造型队列增删、排序、命名、画框和旋转中心调整。

不进入历史：

- 视口平移和缩放。
- 鼠标悬停和工具预览。
- 临时选区边界变化，除非该变化触发像素操作。
- 打开或关闭面板。
- 已提交到 Scratch VM 的外部导入操作。

#### 实现策略

- 元数据操作使用 Command 模式保存正向和反向补丁。
- 像素操作按固定瓦片保存 before 和 after 数据，避免每次复制整张 ImageData。
- 每个像素事务同时保存 beforeSelection 和 afterSelection；撤销像素时恢复匹配的选区。仅移动选区边界仍不单独出现在可见历史中。
- 连续滑块调整在拖动期间合并，松开后只生成一个历史条目。
- 一个笔画只生成一个历史条目。
- “选区复制为图层并加入造型队列”作为原子事务，只撤销一次。
- 新操作发生后清空重做栈。

#### 容量策略

- 默认最多 100 个操作。
- 历史像素数据软上限 256 MB。
- 超过上限时从最旧记录开始压缩或淘汰，并保留当前文档基线。
- UI 显示可撤销操作名称，例如“撤销：色度抠图”。

#### 本地恢复

- 恢复存储包含 documents、bitmapRevisions 和 recoveryHeads 三个对象仓库。位图键为 documentId + bitmapId + revision，文档 manifest 只引用已提交 revision。
- 文档变更停止 2 秒后，先准备新增 Blob，再在同一个 IndexedDB 事务中写入位图 revision、manifest 和 recovery head；事务失败时旧 head 保持有效。
- 提交成功后异步清理不再被当前 manifest 或保留恢复点引用的旧 revision，禁止先删旧数据再写新数据。
- manifest 记录 schemaVersion、位图尺寸、字节长度和校验摘要；恢复时发现缺块或尺寸不符则拒绝该快照，不生成空白图层。
- 数据库升级提供逐版本迁移；未知的更高 schemaVersion 只允许导出原始 Blob，不覆盖数据。
- IndexedDB 恢复属于尽力能力。QuotaExceededError、隐私模式拒绝或空间不足时暂停自动恢复并明确提示，但不破坏内存中的当前文档。
- 快照保存当前文档、图层位图、效果和造型队列，不承诺跨刷新保留完整撤销栈。
- 应用异常关闭后，下次进入画布提示恢复，并提供“放弃恢复数据”和“清除本地画布数据”。

### 7.10 导出与下载

#### 导出类型

1. **合成 PNG**：按合成画框导出全部参与合成的可见图层。
2. **当前图层 PNG**：按当前图层画框或非透明边界导出。
3. **全部造型 PNG**：按造型队列逐项导出，并打包 ZIP。
4. **导入 Scratch**：不下载中间文件，直接生成资产并写入当前 VM。

#### 文件命名

- 合成图：文档名.png。
- 单造型：序号-造型名.png，例如 01-待机.png。
- ZIP：角色名-造型.zip。
- 文件名移除 Windows 非法字符，空名称回退为“造型N”，重名追加序号。

#### 输出规则

- 角色和造型只使用 PNG，保留 Alpha。
- 不用 JPEG 输出透明角色。
- 下载 PNG 的解码像素必须与导出预览一致；导入 Scratch 的位图统一使用 bitmapResolution=2，并按 Asset 像素与 Scratch 逻辑单位的公式预览。
- 导出前检查空画框、全透明造型、超限尺寸、重复名称，以及旋转中心是否为有限值并处于实现安全范围；中心位于画框外只警告，不自动夹紧。
- 批量导出显示逐项进度。取消会停止尚未开始的造型；正在执行的 canvas.toBlob 本身不可中断，完成后丢弃结果。ZIP 在独立 Worker 中由 fflate 生成，取消时可终止 Worker。开始前估算全部 PNG 与 ZIP 峰值内存。
- 全透明造型默认阻止 Scratch 导入，用户明确确认后才允许继续。

### 7.11 导入 Scratch

#### 导入目标

- **新角色**：使用造型队列，一个或多个造型条目创建为同一个角色的 costumes。
- **舞台背景**：使用合成画框，将参与合成的可见图层栅格化为一个 backdrop，不把各图层拆成多个背景。

背景导入默认提供“适应 480×360”“填满 480×360”和“保持原始尺寸”三种模式。这里的 480×360 是 Scratch 逻辑尺寸：标准输出应栅格化为 960×720 Asset 像素，设置 bitmapResolution=2，旋转中心为 Asset 坐标 (480, 360)。适应模式保留完整内容并允许透明留边，填满模式保持比例并裁掉超出部分，禁止默认使用非等比拉伸。“保持原始尺寸”必须同时显示 Asset 像素和除以 2 后的 Scratch 逻辑尺寸。背景继续通过 ScratchAssetAdapter 的 addBackdrop 入口写入 VM，但不再依赖 bitmapResolution=1 的隐式放大和 Asset 重写。

#### 新角色默认行为

- 创建一个新的 Scratch 角色。
- 所有启用且校验通过的造型条目按队列顺序写入该角色。
- 角色名称默认来自文档名，允许导入前修改。
- 第一个造型为 currentCostume。
- 初始位置为舞台中心。
- 初始方向 90，旋转方式 all around。
- 初始大小按 Scratch 逻辑尺寸计算，不直接使用 PNG 像素。对每个造型计算 logicalSpanX = 2 × max(rotationCenterX, assetWidth - rotationCenterX) / bitmapResolution，Y 同理；取全部造型的最大跨度后，将角色限制在 384×288 逻辑单位内。默认 initialSize 不超过 100%，不自动放大小角色；用户可关闭自动适配。

#### 补偿式提交事务

多造型导入必须满足“全部成功或不留下半成品”：

1. 先在内存中栅格化、编码并校验全部造型，任何可预期失败必须发生在 VM 提交之前。
2. ScratchGuiBridge 记录导入前的 runtime target ID 集合，并生成本次事务 ID。
3. ScratchAssetAdapter 读取 PNG Uint8Array，用直接依赖 js-md5 计算 32 位十六进制 assetId，设置 md5ext=assetId + '.png'，并构造下述稳定的普通 JSON 内嵌 Asset；此时不预调用 storage.createAsset。
4. 一次调用 addSprite，传入包含全部 costumes 和内嵌 Asset 描述的角色 JSON，让 VM 的反序列化流程创建最终 Asset。Scratch parser 要求 assetId 匹配 32 位 MD5，VM 创建后的最终 assetId 必须与字节 MD5 一致。
5. 调用结束后由 Bridge 对比 target ID 集合。成功时必须恰好新增一个角色，并校验其 costumes 数量、顺序、bitmapResolution 和旋转中心。
6. 若调用抛错或后置校验失败，对比 target ID 集合；如安装阶段产生了新角色，调用 VM 公开的 deleteSprite 删除该目标，然后再次读取 target 集合确认恢复到提交前状态。
7. deleteSprite 本身若抛错或删除后 target 仍存在，Bridge 进入 fatal-import 状态，禁用继续导入并提示用户重新加载最近一次已保存 SB3；不得把这类情况报告为已回滚成功。
8. Scratch Storage 没有公开的 Asset 删除 API，不访问 builtinHelper.assets 等内部缓存。未挂到 target 的临时 Asset 对象交由垃圾回收，完成判定只以项目 target 不留半成品为准。
9. 校验成功后显式选中新 target，返回 targetId 和安装后的 costume assetId 列表，再显示成功状态。

不能循环调用“新增单造型”后把异常留给用户处理。addSprite 也不被假设为数据库式原子事务；产品保证来自“提交前完整校验 + Bridge 检测新增 target + deleteSprite 补偿”，并必须注入 PNG 解码、皮肤创建和 target 安装阶段故障进行测试。

      data: number[]; // 按 Uint8Array 顺序显式 Array.from，不依赖 JSON.stringify 的类型行为
    }

    interface CostumeExport {
      name: string;
      blob: Blob;
      assetWidth: number;
      assetHeight: number;
      rotationCenterX: number; // Asset 像素坐标
      rotationCenterY: number; // Asset 像素坐标
      bitmapResolution: 2;
    }

    interface SpriteExport {
      name: string;
      costumes: CostumeExport[];
      initialSize: number;
    }

    interface ImportedSpriteResult {
      targetId: string;
      costumeAssetIds: string[];
    }

    importCostumeSet(bridge, spriteExport): Promise<ImportedSpriteResult>

ScratchAssetAdapter 负责把导出结果转换为可序列化角色描述。每个 costume 同时携带合法 assetId、md5ext、dataFormat、bitmapResolution、中心和 InlineBitmapAssetWire。ScratchGuiBridge 负责 VM 提交、target 差异检测、补偿删除和选中新增角色。CanvasWorkspace、图层面板和导出器都不得直接读写 runtime.targets。

#### 重复导入

MVP 每次点击都创建新角色。按钮提交后立即禁用，并使用事务 ID 防止双击重复创建。后续版本可增加“替换上次导入”或“追加到当前角色”。

#### SB3 持久化

导入结果必须满足：

- project.json 中只有一个新增角色 target。
- 该 target 的 costumes 数量等于造型队列数量。
- 每个造型队列条目对应一个 costume 记录和有效 PNG 引用；内容完全相同的 PNG 允许按 Scratch 内容寻址机制共享同一个 assetId 和 SB3 文件条目。
- bitmapResolution 固定为 2，rotationCenterX、rotationCenterY 使用 Asset 像素坐标，名称正确。
- 保存 SB3、刷新页面、重新加载后，解码像素、透明通道、逻辑尺寸、顺序和中心保持一致；不要求 PNG 压缩字节或 assetId 与导入前完全相同。

### 8.1 状态所有权

- CanvasDocument Store：文档元数据的唯一事实来源。
- Bitmap Store：原始像素和编辑后像素的唯一事实来源。
- Renderer：只读取状态并绘制，不拥有业务状态。
- Interaction Controller：把指针和键盘事件转换为命令。
- History Manager：提交、撤销和重做命令。
- Costume Exporter：按造型条目栅格化 PNG。
- ScratchAssetAdapter：将 PNG 字节和元数据转换为可序列化角色描述，不直接拥有 runtime target。
- ScratchGuiBridge：提交角色描述、检测新增 target、失败补偿删除并选中导入结果。

不得把画布渲染库的节点树直接序列化为业务文档，也不得让 Vue 组件各自保存一份图层数组。

## 9. 技术架构

### 9.1 推荐技术路线

- Vue 3：工作区和面板 UI。
- konva：视口、节点变换、控制柄和命中测试，作为项目直接依赖；不把 Konva 节点作为业务状态。
- Canvas 2D：确定性栅格化、PNG 输出和像素工具。
- Web Worker：色度抠图、填充、Alpha 计算和批量编码。
- OffscreenCanvas：能力检测通过时在 Worker 中处理；不支持时回退主线程分片执行。
- idb：IndexedDB 事务、版本迁移和错误封装，作为项目直接依赖。
- fflate：在 Worker 中流式生成造型 ZIP，作为项目直接依赖，不使用 Scratch 包的传递依赖。
- js-md5：按 Scratch parser 要求为内嵌 PNG 生成 32 位 assetId，作为项目直接依赖，不借用 scratch-storage 的传递依赖。

实施前先用一个技术 Spike 验证 Konva 在旋转图层上的文档坐标选区、逆矩阵命中、像素级绘制和高 DPI 导出。若 Spike 不满足像素一致性，再替换视图适配层，文档模型和导出器不随之改变。

### 9.5 已验证边界与风险

| 风险 | 约束与验证 |
| --- | --- |
| Scratch VM 位图转换 | 锁定 15.0.1，角色和背景统一 bitmapResolution=2；升级 @scratch/scratch-vm 时必须重跑像素、中心和 SB3 回归。 |
| addSprite 不是数据库事务 | 提交前完成全部编码；Bridge 通过 target ID 差异和 deleteSprite 补偿，补偿后再次核对集合；删除失败进入 fatal-import，测试反序列化、皮肤创建、安装和回滚故障。 |
| 内嵌 Asset 是版本锁定契约 | 显式使用合法 MD5、固定 AssetType 普通对象和 number[] 字节；阶段零验证 parser/VM 往返，VM 升级不兼容时切换标准 sprite3 ZIP。 |
| Scratch Storage 无公开删除 API | 不访问 builtinHelper 等内部缓存；只保证项目 target 不留半成品，临时未引用对象由垃圾回收。 |
| 预览与导出双渲染漂移 | Canvas 2D 栅格器是像素事实来源，Konva 只显示交互预览；关键操作执行预览与导出 fixture 对比。 |
| IndexedDB 配额和隐私模式 | 恢复为尽力能力，使用原子 head、完整性检查和配额错误状态；不能把自动恢复作为唯一保存方式。 |
| 浏览器和移动端内存差异 | 产品上限之外仍做运行时分配探测，移动端使用更低软上限，所有大任务可失败恢复。 |
| AI 纯色背景不精确 | suggested_key_color 只作提示，实际取色、容差和手工修补始终保留。 |

## 11. 性能与资源限制

### 11.1 目标

- 2048×2048 单图上平移和缩放接近 60 FPS。
- 2048×2048 色度抠图预览在常见桌面设备上 500 ms 内更新。
- 笔画延迟目标低于 50 ms。
- 四个 1024×1024 造型导出时提供持续进度，主界面不能长时间无响应。

### 11.2 内存控制

RGBA ImageData 每像素约 4 字节，2048×2048 单副本约 16 MB。原图、效果预览、图层副本和历史可能快速放大内存，因此：

- Bitmap Store 避免同一位图无意义复制。
- 效果预览使用可复用缓冲区。
- 历史使用瓦片差异，不保存整图快照。
- 视口缩略图与原图分离缓存。
- 文档预计内存超过 512 MB 时阻止继续复制大图层，并提供合并、降采样或清理历史选项。
- 页面隐藏时释放可重建的 GPU 纹理和预览缓存，但保留文档状态。

## 12. 错误处理

| 场景 | 行为 |
| --- | --- |
| 文件格式不支持 | 保留当前文档，提示支持的格式。 |
| 图片解码失败 | 不创建空图层，释放临时资源。 |
| 图片过大或 Canvas 分配失败 | 展示原尺寸和预计内存，提供等比降采样，不反复尝试同一分配。 |
| Canvas 被跨域污染 | 拒绝导出，并指出具体图片来源；产品流程默认不允许此状态出现。 |
| Worker 失败 | 终止当前像素事务，恢复操作前位图。 |
| 历史空间不足 | 淘汰最旧历史并提示可撤销范围已缩短，不破坏当前状态。 |
| IndexedDB 配额或事务失败 | 保留内存文档，暂停自动恢复并提示；旧 recovery head 不变。 |
| 造型画框为空 | 阻止导出并定位到对应造型。 |
| 造型全透明 | 默认阻止 Scratch 导入，可由用户明确确认。 |
| Scratch 尚未就绪 | 保留画布文档，允许稍后重试。 |
| 角色反序列化失败 | 提交前失败时不产生 target；不尝试删除 Storage 内部缓存。 |
| VM 安装或后置校验失败 | Bridge 对比 target ID，删除本事务新增角色并复核集合；成功补偿后不清空画布，允许重试。 |
| deleteSprite 补偿失败 | 进入 fatal-import，禁用继续导入，不声称回滚成功，提示重新加载最近一次已保存 SB3。 |
| 用户连续点击导入 | 首次提交后禁用按钮，使用事务 ID 去重。 |

## 13. 安全与隐私

- 本地上传图片不发送到生图后端或第三方服务。
- IndexedDB 恢复数据仅保存在当前浏览器来源下。
- 不把图片像素写入 localStorage，避免容量和同步阻塞问题。
- 不接受未经净化的 SVG。
- 不直接加载任意远程 URL。
- 导出文件名需要过滤路径分隔符和控制字符。
- 错误日志不记录完整 Base64 图片和用户文件内容。
- 返回 Scratch 后不自动删除画布文档，只有用户明确关闭或清除时释放恢复数据。

## 14. 可访问性与交互质量

- 所有工具按钮提供中文 aria-label 和 tooltip。
- 当前工具、锁定、隐藏、已加入造型等状态不能只依赖颜色表示。
- 图层和造型列表支持键盘上下移动、重命名和排序。
- 焦点进入全屏工作区后保持焦点约束，关闭后返回触发入口。
- 透明棋盘格、选区线和控制柄在浅色和深色图片上都应可见。
- 色度抠图预览提供 Alpha 蒙版模式，避免色觉差异导致无法判断。
- 长任务使用可读进度状态，不只显示旋转动画。

## 15. 验收标准

### 15.1 主验收场景：四宫格角色

准备一张 2048×2048、纯色背景、2×2 排列的角色动作图，执行以下步骤：

1. 打开画布并载入原图，原图尺寸保持 2048×2048。
2. 取背景色并应用色度抠图。
3. 背景 Alpha 变为 0，角色内部近似颜色没有被大面积误删。
4. 分别框选四格并复制为四个新图层。
5. 图层面板保留原图和四个造型图层，原图不在造型队列中。
6. 造型队列包含四项，可重命名和拖放排序。
7. 设置统一画框和底部中心后，快速预览切换没有明显位置跳动。
8. Ctrl+Z 一次完整撤销最后一次“复制图层并加入造型”，重做后完整恢复。
9. 导出 ZIP 得到四个带透明通道的 PNG，文件顺序和名称正确。
10. 导入 Scratch 后只新增一个角色，该角色有四个造型。
11. Scratch 造型顺序、名称、透明通道和旋转中心与预览一致。
12. 下载并重新加载 SB3 后结果保持不变。

### 15.2 像素编辑场景

- 橡皮擦真实修改 Alpha，而不是涂白。
- 画笔和填充只修改当前未锁定图层。
- 单次笔画只需一次撤销。
- 800% 以上像素网格不进入导出 PNG。

### 15.3 历史与恢复场景

- 图层排序、色度抠图、像素编辑、造型中心调整均可撤销和重做。
- 新操作发生后重做栈清空。
- 刷新页面后可恢复最后文档状态，最终像素和造型队列一致。
- 平移、缩放不污染撤销栈。

### 15.4 失败场景

- 模拟第二个 PNG 编码或角色反序列化失败，提交前不得产生新 target。
- 在皮肤创建和 target 安装阶段注入失败；若曾新增 target，Bridge 必须调用 deleteSprite 补偿并复核 target 集合。
- 注入 deleteSprite 失败或删除后 target 残留，Bridge 必须进入 fatal-import，禁用后续导入且不得显示成功。
- 模拟 addSprite 抛错后，画布状态和造型队列完整保留，且不得访问 builtinHelper.assets 清理。
- 导入按钮快速双击只创建一个角色。
- 全透明造型、空画框和超限尺寸在进入 VM 前被识别。

- 导入一个四造型角色。

- 保存 SB3，解压检查 project.json、四个 costume 记录、bitmapResolution=2 和有效 PNG 引用；相同像素允许资源去重，再重新加载。
- 断开外网后完成上传、编辑、导出和 Scratch 导入。
- 1280×800、1024×768 和平板横屏无工具重叠。

## 18. 关键产品决策

1. **工作区无边，导出必须有边。** 使用合成画框和造型画框解决无限空间无法确定 PNG 尺寸的问题。
2. **图层不直接等于造型。** 使用显式造型队列，避免辅助图层、原图或临时图层被误导入。
3. **复制选区默认保留选择框。** 这比自动紧边更适合 Scratch 动画，能减少造型切换跳动。
4. **旋转中心是首要功能，不是高级设置。** 多动作角色若中心不一致，即使抠图正确也无法直接使用。
5. **色度抠图默认移除相邻背景。** 保护主体内部与背景近似的颜色。
6. **多造型导入对用户必须全有或全无。** 不假设 addSprite 天然原子，通过提交前校验、target 差异检测和 deleteSprite 补偿实现。
7. **画布状态与 Scratch 状态分开管理。** 画布撤销不尝试删除已导入角色，Scratch 导入是明确提交边界。
8. **保留原始像素。** 现有单图导入中的目标尺寸缩放不能前置到画布入口。
9. **MVP 只做栅格图层和 Normal 混合。** 先保证角色素材闭环，不提前扩展为通用 Photoshop。

## 19. 完成定义

只有同时满足以下条件，功能才视为完成：

- 用户可以从 AI 结果或本地文件进入无边画布。
- 上传、裁剪、色度抠图、像素编辑、图层和历史均可用。
- 四宫格可拆成四个独立透明图层。
- 图层可配置为有序造型，并可统一画框和旋转中心。
- 可下载合成 PNG 和造型 ZIP。
- 可一次创建一个包含多个造型的 Scratch 角色，角色和背景位图均遵循 bitmapResolution=2 坐标契约。
- 所有可恢复导入失败经过补偿后不留下半成品角色，且不依赖 Scratch Storage 内部缓存删除；补偿自身失败时进入 fatal-import 且不误报成功。
- SB3 保存和重新加载后，造型记录、解码像素、逻辑尺寸和旋转中心完整。
- 本地编辑流程无额外第三方网络请求。
- 单元、像素、组件和端到端测试覆盖主流程及失败回滚。
